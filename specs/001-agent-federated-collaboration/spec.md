## User Scenarios & Testing *(mandatory)*

### User Story 1 - 个人独立完成真实 Agent 工作 (Priority: P1)

个人专业用户在受控的本地或 VPC 工作环境中，从目标输入、工具执行、风险确认到产物保存完成一项真实任务；无需先建团队、邀请成员或公开个人内容，并可在之后继续历史任务。

**Why this priority**: 通用 Agent 是产品底座和日常入口。个人闭环不成立时，共享、交接和联邦协作都没有可靠基础。

**Independent Test**: 在受支持的干净主机上准备工作环境，仅以一名新用户完成包含工具调用和产物保存的任务，随后重启客户端与工作环境并继续该任务，即可独立验证本故事价值。

**Acceptance Scenarios**:

1. **Given** 一名没有团队配置的新用户和可用工作环境，**When** 用户选择工作环境与模型并提交任务目标，**Then** 用户能完成多轮执行、必要工具调用、文件处理和产物保存，全程不被要求邀请其他成员。
2. **Given** 一个已有历史记录和产物的个人任务，**When** 用户关闭并重新打开客户端或重启工作环境，**Then** 用户能按保留策略搜索、重新打开并继续该任务，历史、工作文件与产物未静默丢失。
3. **Given** 多个并存个人任务，**When** 用户在任务之间切换，**Then** 各任务的执行状态、个人草稿和显示偏好分别保留，可并行执行的数量受明确资源规则约束。
4. **Given** 用户只使用图形界面，**When** 用户进行新建、模型选择、审批、文件查看、历史恢复和归档，**Then** 无需打开终端即可完成这些核心操作，并能识别连接状态、任务是否最新及待处理风险。

### User Story 2 - 将个人工作自然升级为团队共享现场 (Priority: P2)

任务发起者在需要同事参与时选择性共享既有工作；负责人也可以直接创建团队工作间。成员围绕同一目标、上下文、执行过程和产物协作，同时清楚区分讨论、指令建议和直接 Agent 指令。

**Why this priority**: 共享工作现场是团队减少重复调查、形成统一进展认知的基础，也是个人产品转化为协作产品的关键路径。

**Independent Test**: 从一个包含历史、上下文和产物的个人任务开始，仅开放选择性共享、成员角色、三类输入和共同查看能力，即可验证第二名成员能否产生有效协作而不获得私人内容。

**Acceptance Scenarios**:

1. **Given** 一个包含私人偏好、模型凭据、本地草稿和正常工作记录的个人任务，**When** 发起者预览并选择共享范围后开启共享，**Then** 仅被选历史、上下文、结论与证据、材料和产物进入工作间并保留时间与作者，默认排除内容对其他成员不可见。
2. **Given** 负责人创建工作间，**When** 名称、目标、完成标准、工作环境、Agent 配置、初始成员或可见范围尚未满足要求，**Then** 只能保存草稿；补齐并指定所需操作与审批责任后才能开始任务。
3. **Given** 第二名成员首次加入工作间，**When** 该成员查看概览和共享上下文，**Then** 无需口头转述即可理解目标、完成标准、当前状态、关键决定、阻塞和最新产物，并默认可查看受邀时已有的完整历史。
4. **Given** 协作者与当前操作者同时参与，**When** 协作者发送讨论和指令建议而操作者发送直接指令，**Then** 三类内容始终可区分；讨论不影响 Agent，建议仅在采纳或编辑后采纳后生效，且建议人和操作者署名均保留。
5. **Given** 五名成员同时查看且两人同时尝试开始任务，**When** 状态发生变化，**Then** 所有成员看到一致的关键状态，只产生一个活动任务，仅查看的成员不会被计为有效协作者。
6. **Given** 工作间启用了 P1 提醒、模板与统计，**When** 用户保存并复用一个模板，或发生审批、交接、提及、完成、失败和待人工确认事件，**Then** 模板能恢复所选目标、上下文与审批配置，相应成员收到对应提醒，统计按有效行为而非消息数量计算。
7. **Given** 同一周内一个工作间有登录围观但无有效贡献，另一个工作间完成任务且有两名成员产生不同有效行为，**When** 计算 Stable 北极星，**Then** 仅后者计入，且分析记录不包含指令、讨论、文件或私人问答正文。

### User Story 3 - 在副作用发生前保持任务安全可控 (Priority: P3)

操作者可以开始、纠偏、排队和停止任务；审批人在高风险动作生效前理解其内容、影响和理由并作出决定。异常或结果不确定时，团队获得诚实、可恢复的状态，而非被引导盲目重试。

**Why this priority**: 真实工具和文件操作会带来实际副作用。没有事前授权与不确定状态处理，共享执行无法用于高价值工作。

**Independent Test**: 使用包含文件修改、外部操作、停止与排队指令的任务，分别执行批准、拒绝、超时、内容变化和运行中断场景，即可独立验证安全闭环。

**Acceptance Scenarios**:

1. **Given** Agent 请求修改文件或改变外部状态，**When** 具备权限的审批人尚未批准，**Then** 动作不产生副作用；审批人无需阅读整段会话即可看到发起人、完整动作、理由、影响范围、风险和有效期。
2. **Given** 一个已获批准的高风险请求，**When** 操作内容或影响范围发生实质变化，**Then** 原批准立即失效并需重新审批；拒绝、默认 15 分钟超时和异常分别呈现明确状态并通知操作者与 Agent。
3. **Given** 当前操作者不具备独立审批例外，**When** 其尝试批准自己的高风险动作，**Then** 系统阻止自我审批；只有管理员显式开放单人试用例外时才可执行，且保留醒目记录。
4. **Given** 一个正在执行且含排队指令的任务，**When** 操作者二次确认停止，**Then** 当前任务尽快停止，既有记录与产物保留，排队指令保留但不自动继续，用户可逐项处理。
5. **Given** 工作环境异常中断或某副作用是否生效无法确定，**When** 成员查看任务，**Then** 状态为待人工确认并保存最后已知进展，不将其描述为确定成功或失败，也不自动重放或建议直接重复执行。

### User Story 4 - 不中断现任操作者完成责任交接 (Priority: P4)

接收者在正式接受操作权之前，通过结构化摘要和私人只读问答理解目标、已做工作、证据、风险、阻塞和下一步；准备过程不暂停主任务、不污染公共时间线，也不扩大其数据权限。

**Why this priority**: 低打扰、可核实的接手是产品的核心差异化，直接减少同步会、重复解释和错误接手。

**Independent Test**: 在一个持续运行的共享任务中邀请另一名具备操作角色的成员接手，让其进行多次私人问答、核对来源、发布澄清并接受或拒绝交接，即可独立验证本故事。

**Acceptance Scenarios**:

1. **Given** 当前操作者发起交接且任务正在运行，**When** 接收者查看交接摘要并接受操作权，**Then** 摘要包含目标、完成标准、任务状态、关键决策、已完成工作、待审批项、排队与待办、产物和阻塞；操作权转移但任务不无故停止或重启。
2. **Given** 接收者尚有背景疑问，**When** 其进入“准备接手”并进行私人问答，**Then** 其不能开始、纠偏、排队、停止、审批、执行真实工具或修改文件；问答默认仅本人可见，公共时间线无新增内容，主任务持续运行。
3. **Given** 一条涉及背景事实的私人回答，**When** 接收者核对它，**Then** 回答关联可查看来源和记录时间；记录不足或内容仅为推测时显著说明，不以完整但虚构的背景作答，也不借用他人权限。
4. **Given** 准备期间目标、操作者、关键决策、风险或阻塞发生实质变化，**When** 接收者准备接受操作权，**Then** 其在确认前看到“背景已变化”提醒、最新记录时间和仍未解决问题，并可更新准备视图。
5. **Given** 接收者整理了问答澄清，**When** 其选择发布，**Then** 发布前可编辑并选择讨论、共享上下文或交接说明等范围；Agent 的私人回答不会自动成为已确认事实，退出或拒绝交接不影响原操作者。
6. **Given** 当前操作者离线超过 2 分钟或负责人必须立即介入，**When** 其他操作者申请接管或负责人强制接管，**Then** 仅一名申请者成功，强制接管必须填写理由；原操作者重连后不会误认为自己仍拥有操作权。

### User Story 5 - 交付有证据、可复核、可沉淀的结果 (Priority: P5)

复核者将关键结论绑定来源、确认人、适用范围和有效状态；来源变化时定位受影响决策、产物和完成判断。任务结束后，未参与者可通过档案与导出理解决策过程、最终结果和遗留问题。

**Why this priority**: “活证据”把共享执行提升为共享可信结果，档案则让一次性会话成为可复用的团队工作记录。

**Independent Test**: 创建多项引用同一来源的关键结论，改变或使该来源失效，复核受影响项并完成任务确认和档案导出，即可独立验证从依据到交付的完整链路。

**Acceptance Scenarios**:

1. **Given** Agent 建议一条关键结论及其来源，**When** 没有具备权限的成员确认或有效来源不足，**Then** 结论保持未验证，不能被无提示地标为已确认，也不以模型置信分代替人工判断。
2. **Given** 多项结论、完成标准和产物依赖同一工作间来源，**When** 来源被更新、替换、撤销或标记失效，**Then** 直接依赖项进入待复核，用户看到全部已知受影响对象；系统不自动推翻决策、删除产物或撤销外部动作。
3. **Given** 来源之间互相冲突或外部来源未接入持续监测，**When** 用户复核，**Then** 系统呈现冲突与各自来源，不自动选边，并展示最后确认时间，不宣称已实时验证外部事实。
4. **Given** 任务存在缺证、失效或待复核的关键结论，**When** 用户尝试标记完成，**Then** 用户必须补齐依据、改为部分完成，或由负责人记录例外理由；例外不会消除缺证与复核历史。
5. **Given** 工作间已归档，**When** 有权限的成员搜索或导出档案，**Then** 工作间保持只读，主要记录以通用可读形式呈现，产物清单与文件可对应，缺失、截断、不可访问及结果未知项显著标注，导出人、时间与范围被记录且署名保留。

### User Story 6 - 按任务贡献跨设备、跨所有者的环境能力 (Priority: P6，Federated Beta)

资源所有者在默认关闭、三级启用的 Beta 边界内配对本人节点，按任务贡献指定文件快照或固定工具，分别控制读取、模型外发、成员可见、跨域传播和本地修改应用，并能随时暂停、撤销或隔离。

**Why this priority**: 联邦能力解决资源不宜集中上传、环境无法复制和外部专家不应获得长期账号的问题，但其价值与安全必须独立验证，不能拖累 Stable 核心。

**Independent Test**: 使用至少两名不同资源所有者的节点完成一项真实任务，覆盖快照、固定工具、独立外发许可、跨域结果、撤销、离线和回执导出；即使 Beta 全部关闭，Stable 故事仍可独立运行。

**Acceptance Scenarios**:

1. **Given** 新团队、既有团队或刚完成升级的部署，**When** 管理员未显式开启 Beta，**Then** 联邦能力默认关闭且不会请求节点资源；团队、工作间、节点三级启用和具体资源授权缺一不可，配对节点本身不共享任何文件或工具。
2. **Given** 所有者选择文件或目录，**When** 请求方获得短期只读授权，**Then** 仅能访问明确包含的快照范围、版本、操作、接收方和期限；指向范围外的路径或链接被拒绝并留下回执，服务器已认证也不能替代节点本地授权。
3. **Given** 已允许读取某来源但未允许模型外发或跨域传播，**When** Agent 尝试发送原文、摘要或派生结果，**Then** 新行为被独立判断和阻断；派生结果默认继承最严格来源限制，降低限制必须由有权限者复核。
4. **Given** A 节点内容要求读取 B 节点、向外部模型发送内容或写入 C 节点，**When** Agent 处理该内容，**Then** 系统将其视为新的权限请求而非原任务自然延伸，拒绝后不能换工具、摘要、日志或错误通道绕过，受影响结论进入待复核。
5. **Given** 所有者提供固定工具和文件修改建议，**When** Agent 执行工具或生成修改，**Then** 未登记的任意命令与命令串联被拒绝，参数、输出和预算受限；文件修改默认形成差异建议，由所有者处理版本冲突并另行授权在本地应用，不直接写回。
6. **Given** 节点离线、授权到期或被撤销、预算耗尽、执行结果未知，**When** 任务继续或权限请求被重放，**Then** 新访问立即停止，缓存是否可用遵循原授权，失效权限不因重启复活，可能产生的副作用不自动重放且待人工确认。
7. **Given** 所有者查看“我的环境”，**When** 节点被读取、执行、外发、传播、生成或应用修改、拒绝或撤销，**Then** 所有者持续看到活动暴露、数据去向与关联授权，可筛选和导出本人节点回执；记录缺失被标记，所有者可立即暂停或隔离且他人不能远程解除。
8. **Given** 多节点任务发生交接或外部专家到期退出，**When** 接收者承担操作权或专家身份失效，**Then** 只读任务级授权可按原期限保留，高风险执行与本地修改应用重新确认，接收者不继承私人可见数据，专家既有贡献与署名保留。
9. **Given** 一周内一个多节点任务只有单一所有者贡献且回执不完整，另一个任务由两名不同所有者的节点有效贡献且 Grant、回执和结果确认完整，**When** 计算 Beta 补充北极星，**Then** 仅后者计为每周完成的真实多环境任务。

### Edge Cases

- 两名成员同时编辑同一目标或上下文时，后提交者必须看到版本冲突，不得无提示覆盖。
- 工作间已归档、成员被停用或移出后，历史贡献仍保留署名，但不能再新增内容或获得后续受限内容。
- 非成员、无权限角色或受限工作环境的访问请求，即使持有链接也不能发现或读取受限内容。
- 文件超过默认 20MB、格式不可预览、上传中断或来源无法确认时，必须说明原因、提供可行处理并禁止冒充 Agent 产物。
- 上传的可执行文件只能作为文件保存，不因上传或预览自动运行；共享与导出前提醒可见范围和潜在敏感内容。
- 已共享内容不能通过“撤销共享”伪装成从未被访问；撤销资源授权也不承诺召回已合法获取的副本。
- 过长上下文不得被静默截断后提供给 Agent；历史任务必须继续使用其开始时的上下文与文件版本。
- 客户端断线或页面关闭不等于批准、授权、交接接受或任务完成，恢复后必须指出内容可能过期并同步主要变化。
- 多项结论引用同一来源时只提醒一次来源变化，但分别展示每项影响；复核后重新确认仍保留完整失效历史。
- 私人接手问答需要超出接收者权限的信息时必须拒答并说明边界，不能通过公共摘要或分析数据泄露。
- 无依赖的多节点步骤可继续，有依赖的步骤明确等待或失败；局部成功不得伪装为整体成功。
- 受损或恶意节点返回的结果不能仅因“执行完成”就被标为真实或已验证，应支持隔离与人工复核。
- 节点本地策略与团队策略冲突时采用更严格者，资源不足不得成为关闭安全策略或扩大范围的理由。
- Beta 全局、工作间或节点任一停用都必须阻止新访问，且不影响 Stable 任务和用户导出本人有权查看的记录。

## Requirements *(mandatory)*

### Functional Requirements

#### 个人任务、图形界面与工作环境

- **FR-001**: 系统必须允许用户在不创建团队、不配置共享成员的情况下创建并完成个人 Agent 任务，包括多轮执行、工具调用、文件处理和产物保存，不得将个人模式做成只读演示。
- **FR-002**: 系统必须允许用户选择本人有权使用的本地或 VPC Runner、已配置模型及推理选项；模型凭据和敏感配置默认属于个人或管理员，不得因共享而暴露。
- **FR-003**: 个人与共享任务必须一致地支持开始、运行中纠偏、后续排队、停止和历史继续，且明确区分各操作对当前执行的影响。
- **FR-004**: 系统必须保存个人任务历史并支持搜索、置顶、归档和重新打开；多个个人任务可并存，切换时保留各自状态，并行数量受 Runner 资源和用户设置约束。
- **FR-005**: 每名用户必须使用独立身份和独立图形界面完成个人及共享核心流程；界面至少覆盖任务导航、执行时间线、输入、工具与审批、文件与产物、结论与证据、成员与操作权、Runner 状态和设置。
- **FR-006**: 图形界面必须合理展示常见文本、格式化文档、代码、差异和图像，支持长输出折叠、搜索与定位，并提供键盘操作、清晰焦点、深浅色主题及可调整的信息密度。
- **FR-007**: 多名用户同时在线时，系统必须保留各自草稿、滚动位置和显示偏好，同时共享关键任务状态，并持续显示 Runner 连接、内容是否最新、共享状态、当前操作者和待处理风险。
- **FR-008**: Runner 必须支持在受支持的 Linux 主机上以 Docker 方式部署于本地或 VPC，并提供普通用户可遵循的启动、停止、状态检查、备份和升级说明；核心使用不得依赖公共云 Runner 或 Unspool 云端中转。
- **FR-009**: Runner 重启或容器更新后，个人任务、共享工作间、历史、设置和产物必须按保留策略可用；升级前必须提示兼容性与备份要求，不得静默清空工作目录或历史。
- **FR-010**: 系统必须区分 Runner 可用、繁忙、离线、升级中、异常和已停用状态并说明影响；已停用 Runner 不得用于新工作间，已有记录不得被无提示删除。
- **FR-011**: 个人任务开启共享前必须按目标与历史、上下文、结论与证据、参考材料和产物提供选择性预览；模型凭据、私人偏好、本地草稿、私人接手问答及未选择内容默认排除，转换后新工作默认共享且共享状态持续可见。

#### 团队、工作间与共同执行

- **FR-012**: 系统必须支持创建团队、邀请和停用成员、分配管理权限，并由管理员登记 Runner、设置用途、可用成员范围和默认安全策略。
- **FR-013**: 成员只能看到本人有权使用的 Runner；团队管理员不得仅凭管理身份自动获得所有工作间内容或节点资源访问权。
- **FR-014**: 工作间必须支持名称、任务目标、可判断的完成标准、Runner、Agent 配置、初始成员和可见范围；信息不完整时可保存草稿但不能开始任务，高风险任务开始前必须指定操作者和审批人。
- **FR-015**: 工作间默认仅受邀成员可见，新成员默认可见受邀时已有的完整历史；负责人可分配负责人、操作者、协作者、观察者及独立审批、复核权限。
- **FR-016**: 活动任务中不得静默更换 Runner、Agent 配置或联邦模式；目标、完成标准、角色和关键配置的变更必须留痕，并发修改必须提示冲突。
- **FR-017**: 工作间归档后必须禁止新增讨论、指令、任务和产物，同时保留查看、搜索和受控导出能力及所有历史署名。
- **FR-018**: 共享上下文必须覆盖目标与完成标准、事实、决策、约束、待办与阻塞、参考材料，并为每项记录标题、正文、作者、来源、更新时间和当前状态。
- **FR-019**: 每条上下文必须分别表达“成员可见”和“提供给 Agent”；协作者可新增及编辑本人内容，其内容提供给 Agent 前必须由当前操作者确认，讨论、草稿和未采纳建议默认不提供。
- **FR-020**: 上下文修改和移除必须保留历史版本；每次任务必须记录实际获得的上下文版本，进行中的修改默认只影响下一任务，影响当前任务必须显式纠偏，过长内容不得静默截断。
- **FR-021**: 输入区必须始终清楚区分讨论、指令建议和 Agent 指令，切换时保留草稿；非当前操作者尝试直接指令时必须被引导转为建议而非直接执行。
- **FR-022**: 指令建议必须记录建议人、时间和引用材料，支持采纳、编辑后采纳或忽略；采纳后同时保留建议贡献者与实际操作者，已接收指令不得无痕修改。
- **FR-023**: 一个工作间同一时间必须只有一名当前操作者和一个活动任务；只有当前操作者可直接开始、纠偏、排队或停止，重复点击与网络重试不得重复开始任务。
- **FR-024**: 开始任务前必须展示目标、完成标准、Runner 和上下文范围；停止必须二次确认并保留记录与产物，停止后的排队指令默认保留但不自动执行，异常后由用户决定保留、修改、删除或继续。
- **FR-025**: Agent 自称完成不得等同于业务验收完成；操作者或负责人必须将结果确认成完成、部分完成、未完成、失败或取消，并可记录原因。
- **FR-026**: 时间线必须展示讨论、指令、Agent 输出、工具活动、高风险审批、上下文与决策变化、交接、产物及任务状态，并区分执行中、等待审批、正在停止、完成、失败、取消和待人工确认。
- **FR-027**: 高风险、失败和待审批项不得被默认隐藏；长时间无输出必须显示最近更新时间与状态，断线必须提示内容可能不是最新，恢复后同步主要变化，客户端离线不得自动停止任务。
- **FR-028**: 工作间必须提供概览与完整时间线，支持按成员、任务、类型和时间筛选及定位离线期间变化；本次任务用量与费用只在上游数据可靠时展示具体数值，否则标为暂不可得。
- **FR-029**: 观察者必须只读；协作者可讨论、上传材料、维护本人贡献、提交结论与建议但不得直接操作 Agent；操作权、全量上下文编辑、成员管理、归档、复核和导出必须分别遵守角色与附加权限。

#### 高风险审批与操作权交接

- **FR-030**: 修改、覆盖或删除文件，改变环境或外部系统状态，向外发送内容或触发外部操作，以及管理员标记的其他动作必须默认为高风险，并在批准前保持未生效。
- **FR-031**: 审批请求必须展示发起人、关联任务、动作及理由、影响对象与范围、完整可读的语义内容、风险和有效期，使审批人无需阅读整段会话即可理解决策。完整语义内容必须包含全部参数及其作用；秘密值以明确的脱敏占位和秘密引用表示，原始执行载荷仅保留在受控执行边界，动作摘要仍绑定真实规范化内容。
- **FR-032**: 批准必须仅对本次提交内容有效，内容或范围变化后重新审批；默认有效期为 15 分钟，拒绝、超时、审批人离线、页面关闭和网络异常均不得解释为批准。
- **FR-033**: 高风险动作默认禁止当前操作者自我审批；单人试用例外必须由管理员显式开放并保留醒目记录，审批人可填写批准或拒绝理由，Agent 与操作者必须收到结果。
- **FR-034**: 所有批准、拒绝、超时、内容失效和异常必须进入任务记录与档案，并以不同界面状态呈现。
- **FR-035**: 操作权必须支持申请、主动交接、接收者确认或拒绝；交接不得改变任务执行状态，且必须自动包含目标、完成标准、状态、决策、已做工作、待审批、排队与待办、产物和阻塞摘要。
- **FR-036**: 当前操作者离线超过 2 分钟后其他操作者可申请接管，负责人可填写理由后立即强制接管；并发接管只能一人成功，原操作者立即失去直接操作权限但保留原有讨论与贡献权限。
- **FR-037**: 被邀请接收者必须能在接受前进入私人只读准备，查看按角色组织的背景并问答；准备期间不得控制任务、审批、执行真实工具、改变文件或外部系统，也不得影响公共会话和当前 Agent。
- **FR-038**: 私人问答中的背景事实必须关联可查看来源和记录时间，推测、未知与权限不足必须明确表达；只能使用接收者本人有权访问的来源，不得借用原操作者或其他成员权限。
- **FR-039**: 准备期间目标、操作者、关键决策、风险或阻塞发生实质变化时，系统必须在接收者接受前提醒背景已变化并允许更新视图；接受、拒绝或退出不得无故改变原任务。
- **FR-040**: 接收者必须能编辑并选择性发布澄清、保留未解决问题；私人问答默认仅本人可见且分析不采集正文，发布后仍须遵守共享上下文和关键结论确认规则。

#### 活证据、文件与档案

- **FR-041**: 用户必须能把 Agent 输出、讨论或文件内容提炼为事实、假设或决策类关键结论，并记录内容、来源、提出人、确认人、确认时间、适用范围及未验证、已确认、待复核或已失效状态。
- **FR-042**: Agent 可建议结论和来源但不得自行确认；已确认结论原则上必须至少关联一项来源，系统不得以有来源代替真实性判断，也不得以模型置信分替代人工确认。
- **FR-043**: 用户必须能建立关键结论与完成标准、后续决策、产物和待审批动作的关联，并集中查看当前结论、待复核项、缺失依据和最近失效影响。
- **FR-044**: 来源可设置复核时间或有效期限，到期进入待复核而非自动失效；已知来源变化、撤销或失效必须列出受影响项，冲突来源必须并列呈现，任何失效提醒不得自动推翻业务行为。
- **FR-045**: 任务标记完成前必须展示证据覆盖情况；存在缺证、失效或待复核项时，用户必须补证、改为部分完成或由负责人记录例外，例外不得清除既有风险记录。
- **FR-046**: 复核后必须允许重新确认并保留失效、复核与例外历史；未接入持续监测的外部来源必须显示最后确认时间并依赖成员手动复核，不得宣称实时有效。
- **FR-047**: 成员必须能上传参考材料，默认单文件不超过 20MB且管理员可调整；系统应提供常见文本与图片预览、其他格式信息及下载，上传可执行文件不得自动运行。
- **FR-048**: 系统必须区分成员参考材料与 Agent 产物，记录名称、大小、贡献者、时间、关联任务、来源和版本；历史任务保留当时版本，来源不明必须标记待确认，Stable 工作间文件默认对全部成员可见。
- **FR-049**: 工作间档案必须包含基本信息、目标与完成标准、上下文历史、关键结论与证据、讨论与指令、任务、审批、产物和成员贡献，并支持按关键词、成员、任务和时间搜索。
- **FR-050**: 完整档案默认仅负责人可导出，其他成员按工作间设置授权；导出必须采用通用可读形式、对应产物清单与实际文件、标注缺失或不确定内容，并记录导出人、时间和范围。
- **FR-051**: P1 提醒必须覆盖待审批、交接、被提及及参与任务完成、失败或待人工确认；P1 模板和统计可复用常见配置并呈现协作效率，但不得将消息数量或在线时长等同于贡献价值，也不作为 Stable 首发阻断项。
- **FR-052**: 产品分析必须以“每周多人有效协作工作间数量”为 Stable 北极星：仅计入当周完成至少一个 Agent 任务、且至少两名不同成员提交或采纳指令、维护上下文、确认或复核结论、完成交接或审批高风险动作的工作间，登录、围观和在线不计入；以“每周完成的真实多环境任务数”为 Beta 补充北极星，仅计入至少两名不同资源所有者的节点有效贡献且 Grant、访问回执和结果确认完整的任务。系统必须按明确口径记录个人激活、共享转化、有效协作、建议采纳、交接耗时、审批等待、证据覆盖、无扰接手收益、导出和联邦留存指标，且普通交接与无扰接手分开比较；默认仅采集行为元数据，不采集指令、讨论、文件、工具参数、路径、外发内容或私人问答正文。

#### Federated Beta

- **FR-053**: 联邦能力必须默认关闭，团队、工作间和节点三级启用缺一不可，具体资源仍需单独授权；升级不得自动开启或扩大既有授权，关闭 Beta 不得影响 Stable 功能和历史档案。
- **FR-054**: 开启 Beta 前必须展示支持平台、资源类型、已知限制、数据处理路径和安全边界；商业页面与界面必须区分 Stable 和 Beta，并提供版本标识、反馈、安全公告和已知问题说明。
- **FR-055**: 所有者必须能配对、命名、查看和撤销本人本地或 VPC 节点，配对须确认身份、归属、目标团队、支持状态和允许能力；新节点默认已连接但未贡献资源，且不得要求开放公网入站端口。
- **FR-056**: 节点必须区分待确认、在线、繁忙、离线、暂停、撤销、隔离和不兼容，并分别表达设备已配对、策略兼容和安全状态未知，不得把配对成功包装成可信执行证明。
- **FR-057**: 文件资源必须由所有者显式包含并预览数量、大小、子目录、快照时间、接收方和期限；范围外路径、链接逃逸和隐式继承新增目录必须被拒绝，路径与目录结构本身的可见性单独配置。
- **FR-058**: 固定工具必须以所有者理解的名称和用途注册，明确参数及允许值、工作目录、网络需要、超时、输出范围和风险；未声明参数、额外命令串联、任意 Shell 和默认环境继承必须被拒绝，不得把任意命令包装成只读工具。
- **FR-059**: Grant 请求必须说明任务目的、资源、操作、接收方和期限，支持一次、到任务结束、固定时长、缩短范围或拒绝；默认最短可行期限、只读、不可转让、不可转发、不可升级，实质变化必须重新授权。
- **FR-060**: 节点必须对每次访问重新验证当前 Grant 并采用节点与团队策略中更严格者；额外审批不得替代资源所有者，授权和拒绝均须产生含原因、时间、操作者和影响任务的回执。
- **FR-061**: 联邦文件默认读取带来源、所有者、范围、版本、时间和校验信息的快照；来源变化仅提示并由所有者决定新快照，中央缓存与成员访问必须另行明确，未许可缓存不得在节点离线后伪装可读。
- **FR-062**: 大文件、二进制文件和超预算目录必须提供限制与处理选项；跨节点处理必须使用来源与可见范围明确的 Artifact，不得拼接成透明统一文件系统，删除或撤销不得伪造历史读取记录。
- **FR-063**: 固定工具每次执行必须绑定任务、节点、参数、Grant、预算和结果接收方，使用边界明确的干净运行上下文，并呈现等待、运行、取消、成功、失败、超时和结果未知；异常副作用不得自动重放。
- **FR-064**: 对贡献者文件的修改必须默认生成绑定节点、快照、目的和任务的 Patch，不直接写回；所有者必须查看差异、影响和风险，来源变化提示冲突，本地应用属于独立权限并生成新版本与证据。
- **FR-065**: 读取、模型外发、成员可见、公共区和跨域传播必须分别许可；跨域前展示来源、目的、内容类型、数量、接收方和任务原因，派生结果默认继承最严格来源限制，降级必须由有权限所有者复核。
- **FR-066**: 系统不得允许通过摘要、日志、错误、文件名、代码注释、分析埋点或更换工具绕过传播限制；被拒绝的传播必须留下可审计原因，并允许 Agent 在权限内提出替代方案。
- **FR-067**: 来自节点内容的跨节点读取、外发或写入指令必须被视为新权限请求，检查原始目的和各域授权；拒绝后不得换通道重试同一越权目标，相关结论必须标记可能受不可信内容影响并待复核。
- **FR-068**: 多节点计划必须展示步骤、依赖、状态、Grant 和阻塞，各节点仅处理获批步骤；本地拒绝不得被解释为自动改派其他私密资源，无依赖步骤可继续，有依赖步骤须明确等待或失败，重试须受副作用和次数限制。
- **FR-069**: 联邦交接摘要必须包含活动 Grant、剩余期限、受限结果和节点状态；只读任务级 Grant 可保留至原期限，高风险执行和 Patch 应用重新确认，接收者不得继承原操作者私人可见数据，所有者可因交接暂停或撤销。
- **FR-070**: 所有者必须持续看到节点是否被任务使用、当前工作间、资源、操作、请求方、开始时间和数据接收方，并能停止新访问、暂停或隔离；团队成员只能看到其有权查看的回执粒度。
- **FR-071**: 每次读取、执行、外发、传播、Patch 生成或应用、拒绝和撤销必须形成可筛选、可导出的回执，至少包含任务、请求方、资源、操作、时间、结果、数据去向和 Grant；断线补交失败必须标记记录不完整。
- **FR-072**: 所有者必须能限制文件数量与大小、单次读取、输出、执行时长、并发及所支持平台的计算、内存、网络和进程预算；耗尽后停止或拒绝新工作，不自动提额或关闭安全策略，并通知所有者与操作者。
- **FR-073**: 节点离线、撤销、过期、暂停、隔离和 Beta 停用必须按统一规则阻止新访问；撤销后进行中操作须安全停止或标记待确认，只有所有者可解除本人节点隔离，失效 Grant 不得因重启或重放复活。
- **FR-074**: 外部专家必须使用限期身份和限期 Grant，到期后终止个人访问而保留已授权贡献及署名；联邦证据和档案必须保留节点、快照、Grant、执行版本与传播记录，并区分不可访问、已撤销和内容失效。
- **FR-075**: 出现本地授权可绕过、未授权外发或传播、撤销后仍可访问、受限结果泄露、回执缺口无法界定或升级静默扩权等严重情况时，必须能暂停新 Grant 和停用受影响版本，同时保留证据与合法导出能力。

#### 可靠性、安全与发布合规

- **FR-076**: 已被系统确认接受的操作不得因刷新或重连无提示丢失；无法确认的副作用必须保持待人工确认，任务失败必须保留错误说明、最近进展和可行下一步。
- **FR-077**: 所有页面必须提供首次空状态、正常与长时间加载、无权限、内容被更新、操作者变化、Runner 离线、断线恢复、等待审批或人工确认、文件失败和已归档等反馈，并说明发生了什么、是否影响任务及用户可做什么。
- **FR-078**: 凭据与敏感配置不得进入共享讨论、时间线、审批或导出；上传、工具结果和导出须提供敏感风险提示，受限成员的错误与日志不得泄露路径、参数或正文，导出必须受权限控制并留痕。
- **FR-079**: 自有代码发布必须附带 MIT 许可和准确版权声明，品牌、第三方软件、模型、数据、文档与设计资产分别说明权利边界；发布物必须维护包含名称、版本、来源、许可、版权、用途和修改情况的第三方清单。
- **FR-080**: 未经单独许可评审不得复用 PI-Desktop 的代码、样式、构建产物、图标、截图、文案、品牌或识别性视觉组合；设计评审必须保留参考来源、差异与原创记录，来源不清或许可证未知的内容必须阻断发布。
- **FR-081**: Stable 对外发布前必须提供完整的安装、备份、恢复、升级、权限和故障文档；Beta 另须提供支持矩阵、威胁模型、Grant 与数据流、撤销隔离、事件处理和安全公告文档。严重或高危安全问题未解决、关键验收场景未通过或本地拒绝未独立验证时不得发布，Federated GA 前必须完成独立威胁模型评审和第三方安全测试。

## Key Entities *(include if feature involves data)*

- **个人任务**: 仅当前用户可用的完整 Agent 工作，包含历史、上下文、工具活动、产物和私人偏好，可选择性转为共享。
- **团队与成员**: 协作和管理边界；成员具有负责人、操作者、协作者、观察者及可叠加的审批、复核或资源所有者身份。
- **Runner**: 用户授权的本地或 VPC 工作位置，承载任务执行、工作文件与产物，并具有明确可用状态和访问范围。
- **工作间**: 围绕一项持续工作的共享空间，包含目标、完成标准、上下文、讨论、任务、审批、证据、产物和档案。
- **任务**: 一次明确的 Agent 执行过程，可包含纠偏和排队指令；其技术结束与用户业务结果确认分别记录。
- **共享上下文**: 经团队维护、带版本和来源的事实、决策、约束、待办与参考信息，并独立标记是否提供给 Agent。
- **指令建议**: 非当前操作者提出的下一步建议，经操作者采纳后才成为影响 Agent 的指令。
- **操作权**: 当前唯一直接控制工作间 Agent 的责任状态，与成员在线状态和任务运行状态相互独立。
- **关键结论**: 会显著影响后续决策、验收或外部行动的事实、假设或决定。
- **活证据**: 与关键结论绑定的来源、确认人、适用范围、有效状态及复核历史，用于追踪失效影响而非自动证明事实。
- **高风险审批**: 对特定动作内容和影响范围的限时决定，包含批准、拒绝、超时和失效记录。
- **参考材料与产物**: 分别由成员提供或由 Agent 生成的任务输入与输出，具有贡献者、来源、关联任务和版本。
- **贡献者节点**: 资源所有者本地或 VPC 环境的受控入口；配对仅建立连接，不代表已贡献资源。
- **Grant**: 面向任务、目的、资源、操作、接收方和期限的能力授权，默认短期、只读且不可转发。
- **快照**: 某时间点、明确范围和版本的文件资源，任务默认读取它而非无声跟随实时变化。
- **节点 Artifact**: 经许可离开来源域的结果，保留来源、版本、所有者、许可与可见范围。
- **Patch**: 针对指定快照生成的文件修改建议，只有独立授权后才可由所有者或获授权者在本地应用。
- **节点回执**: 读取、执行、外发、传播、修改建议、拒绝和撤销的责任记录，用于问责与复盘，不等同于绝对安全证明。
- **工作间档案**: 任务结束后可搜索、查看和受控导出的完整过程记录，须诚实标注缺失和不确定性。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可用性试点中，至少 80% 的新用户无需团队配置或他人协助，即可完成首个包含工具调用和产物保存的个人 Agent 任务；关闭并重开客户端后，100% 的验收任务可按保留策略找回。
- **SC-002**: 在全部受支持的干净验收主机上，用户仅依据文档即可完成 Runner 启动、状态检查、停止、备份和基本升级，且重启与升级验收中历史、工作文件和产物零静默丢失。
- **SC-003**: 至少 5 个试点团队各完成 5 个真实任务，其中至少 4 个团队在两周内完成首个双人协作任务，且至少 50% 的试点工作间达到“两名成员产生有效协作行为”的定义。
- **SC-004**: 与原流程相比，接手者恢复任务背景的中位耗时下降至少 50%，因交接而重复描述任务背景的中位次数下降至少 30%。
- **SC-005**: 至少 50% 的试点交接使用无扰接手；与普通交接相比，其准备时长和向原操作者追问次数的中位数均下降至少 30%，并单独跟踪接受后 24 小时内返工次数。
- **SC-006**: 试点中标记“完成”的任务，其关键结论有效证据覆盖率不低于 80%；100% 被定义为高风险的动作均有批准、拒绝或超时未执行记录，负责人例外完成不计为有效证据覆盖。
- **SC-007**: 至少 80% 的试点成员能正确区分讨论、指令建议和直接 Agent 指令；至少 80% 的资源所有者能区分读取、模型外发、成员可见和跨域传播，并独立配置常见 Grant。
- **SC-008**: 在正常网络与 Runner 可用时，95% 的常用工作间概览在 3 秒内打开，95% 的普通界面操作在 1 秒内反馈，95% 的 Agent 新输出在 1 秒内呈现；至少 5 个独立客户端同时查看时关键状态一致。
- **SC-009**: 未参与任务的试点成员仅阅读归档后，至少 80% 能正确回答任务目标、关键决定、最终结果和遗留问题；100% 的导出验收样本可由通用阅读工具打开，且缺失、截断、不可访问和结果未知项有显著标注。
- **SC-010**: Stable 的 P0 验收场景 100% 通过，无未解决的高严重度越权、跨工作间数据暴露、明文凭据共享或审批绕过问题；至少 80% 的可用性测试用户无需协助完成核心个人任务和共享交接。
- **SC-011**: Federated Beta 至少支持每工作间 5 个贡献者节点和 20 个活动 Grant 的验收规模；至少 5 个封闭试点团队完成真实多环境任务，其中至少 3 个团队完成多个由不同所有者节点有效贡献且 Grant、回执和结果确认完整的任务。
- **SC-012**: 至少一半联邦试点团队证明存在集中上传难以替代的价值，且无未解决的严重或高危越权、数据流绕过、撤销后访问或失效 Grant 复活问题；若未达到真实复用与安全门槛，Beta 不转为正式能力。
- **SC-013**: 100% 的公开发布物具备准确的 MIT 许可、第三方清单及必要通知，发布审查未发现来源不明、无权使用或未获许可的 PI-Desktop 代码、资产或识别性视觉复刻。
- **SC-014**: Federated GA 仅在至少 10 个团队累计完成 50 个以上真实多环境任务、持续使用至少 8 周并出现多环境任务复购后评审；独立威胁模型评审和第三方安全测试必须完成，严重或高危问题清零，权限与撤销回归持续通过，且资源所有者的理解与独立授权成功率均达到 SC-007 的 80% 门槛。

## Assumptions

- 本规格以 PRD v5.1 为唯一需求基线，包含 Stable MVP 与默认关闭的 Federated Beta；用户故事优先级仅表示增量验证顺序，不替代 PRD 的 P0 与 Beta 发布门禁；P1 提醒、任务模板和跨任务统计可在试点补充，不作为首个 Stable 完整闭环的阻断项。
- 首发产品形态为独立桌面图形界面加本地或 VPC Runner；桌面操作系统的具体支持名单在计划评审时冻结，Runner 的首发部署基线为受支持的 Linux Docker 主机。
- 产品复用 PRD 指定的 pi Agent 持续会话、上下文管理、工具调用、运行中纠偏和后续排队能力，但本规格不限定其接入方式或内部技术方案。
- 工作间默认仅受邀成员可见且新成员可见完整历史；同一工作间文件默认向全部成员公开，不提供 Stable 单文件独立授权，需要不同保密级别的任务应拆分工作间。
- 默认规则为单一当前操作者、单活动任务、操作者离线 2 分钟后可申请接管、高风险审批有效期 15 分钟、禁止自我审批、参考材料单文件 20MB；管理员仅可在 PRD 允许的范围内调整或开放例外。
- 新成员默认角色由邀请人在协作者或观察者中选择；资源所有者、外部专家、审批人和复核者身份可与其他角色叠加，但资源所有者权限独立于团队与工作间管理权限。
- MVP 历史、署名、审批、证据和回执默认持续保留；具体数据保留期限、删除策略及诊断信息保留规则须在上线前由安全与合规评审冻结。撤销只阻止未来访问，不承诺召回已合法获取的副本。
- 未接入持续监测的外部来源由成员手动复核；系统提供来源状态和失效影响管理，不自动判定事实真伪，也不承诺发现所有侧信道泄漏或识别所有敏感信息。
- 联邦 Beta 首期仅覆盖经验证的 Linux 本地或 VPC 贡献者节点、明确文件快照、固定工具模板和本地确认应用的 Patch；不把 Docker 部署本身等同于完整安全隔离。
- 产品分析仅用于回答明确的激活、协作、交接、证据、授权和留存问题，与安全审计分开管理；连接节点数、暴露文件数和远程命令数不视为核心价值指标。
- Unspool 自有代码计划采用 MIT，第三方内容仍遵循各自许可；PI-Desktop 仅作为抽象交互研究输入，默认不复用其代码或资产，任何未来代码级复用均需独立的 LGPL-3.0 合规评审。
- 明确不在本次范围：行业专用知识库或连接器、同工作间多 Agent 并行、自动任务拆分与多 Agent 编排、无约束多人直接操作、跨工作间自动组织记忆、共享文档实时共编、任意历史点分叉、公共云托管 Runner、商业计费、外部平台通知、移动客户端、自动监测所有外部来源、接手阶段真实执行沙盒、任意 Shell、默认直接写回、长期目录同步、内部端口映射和透明统一多节点文件系统。
